# Project Overview

This is a NixOS configuration project for setting up and configuring different computers.
It is currently used mainly to configure macOS systems.
It was initialized with `nix flake --extra-experimental-features 'nix-command flakes' init -t github:dustinlyons/nixos-config#starter-with-secrets`.

## General Guidelines

- Use Nix for system and Home Manager configuration; keep existing file formats for managed dotfiles and helper scripts.
- Follow the existing module structure and naming conventions.
- Keep host-specific configuration in `hosts/` and reusable configuration in `modules/`.
- Prefer small, composable modules over large monolithic files.
- Use meaningful comments only for non-obvious configuration decisions.

## Code Style

- Format Nix files with the formatter defined by the flake: `nix fmt`.
- Follow the formatting style already present in nearby Nix files.

## Nix Commands

- Format all Nix files with `nix fmt`.
- Check Nix formatting without writing changes with `nix fmt -- --fail-on-change`.
- Build the current Darwin/macOS system with `nix run .#build -L --show-trace -- --show-trace`. This app is not currently defined for Linux systems.
- Build and switch the current system with `nix run .#build-switch -L --show-trace -- --show-trace`
- Use nix-output-monitor (`nom`) for more detailed Nix output when building or running other Nix tasks.
- `nom` may be available through the configured Home Manager environment, but do not assume it is installed on clean machines or agent environments.
- The nix-output-monitor pipe examples assume Bash or Zsh because they use `set -o pipefail` and `|&`.
- For repo scripts that use `nix run`, pipe output through nix-output-monitor from nixpkgs, for example `set -o pipefail; nix run .#build -L --show-trace -- --show-trace |& nix run nixpkgs#nix-output-monitor`.
- When using native Nix build commands, prefer JSON logs with nix-output-monitor, for example `set -o pipefail; nix build --log-format internal-json -v |& nix run nixpkgs#nix-output-monitor -- --json`.
- Update all flake inputs with `nix flake update --commit-lock-file` unless the update is only for testing.
- Update a single flake input with `nix flake update <input-name> --commit-lock-file` unless the update is only for testing.

## Commit Messages

- Use Conventional Commit format.
- Keep messages concise and avoid unnecessary detail.
- Commits generated by `nix flake update --commit-lock-file` are exempt from the Conventional Commit rule because this command does not currently support customizing the generated commit message.

## Architecture Principles

- Keep shared behavior in `modules/shared/`.
- Keep Linux-specific behavior in `modules/nixos/`.
- Keep macOS-specific behavior in `modules/darwin/`.
- Keep overlays in `overlays/`.
- Avoid duplicating package and Home Manager configuration between hosts when it can be shared cleanly.
